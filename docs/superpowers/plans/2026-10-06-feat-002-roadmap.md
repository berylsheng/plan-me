## Notes for later plans

Found while writing plans 1 and 2. Each must be handled by the plan named.

- **Plan 3:** check how Supabase's current Expo guide stores the session. `expo-secure-store` warns when a value is over 2048 bytes, and Supabase sessions can be bigger. If so, follow the guide's pattern rather than writing tokens into SecureStore directly. Read the Expo SDK 54 docs before adding packages (AGENTS.md).
- **Plan 3, from plan 2's review:** before the first hosted push, set auth config (password length/requirements, email confirmations on, secure_password_change, site_url and redirect URLs incl. planme://), confirm postgres can delete from auth.users on hosted (fallback: Edge Function with auth.admin.deleteUser), and keep seed.sql off hosted projects and Branching.
- **BUG-003 / BUG-004 / BUG-005** (hyphen dates, extra recurrence, evening edits moving to another year) are deliberately left alone by plan 1, which must not change behaviour. Fix them as separate registry items; BUG-005 is High priority.
